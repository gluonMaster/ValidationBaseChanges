# Constraints - KindEltern Web

Этот файл фиксирует жесткие ограничения и запреты, чтобы модель (и разработчики) не уходили в неверную сторону.

## Продуктовые и процессные ограничения

- Не перепридумывать архитектуру: изменения точечные и минимальные.
- 1 промпт = 1 атомарная правка (для code-change).
- По умолчанию код не править напрямую: изменения кода оформляются как `PROMPT_XX_*.md` для Copilot Agent.
- Документацию (`*.md`) можно править напрямую.
- UI тексты/сообщения: немецкий. Комментарии в коде: английский. PROMPT-файлы: русский.

## Технические ограничения и инварианты

Канонический список инвариантов/контрактов находится в `docs/Spec.md` (разделы 1–4). Здесь — только “напоминалки”:

- `RecordStatus.NORMAL` хранится как `""` → проверка `not record.status`.
- Всегда различать `pkid` и Access/Excel `id`; доменный ключ `(year, id)`.
- Access import: `ACCESS_CONN_STRING_TEMPLATE` собирается через `.format(...)` → DRIVER экранируется как `{{...}}`.
- Patch-импорт `--patch-fields` требует примененных миграций к той же базе данных.

## Ограничения по UI/Frontend

- Без тяжелого SPA на первом этапе: Django templates + легкий JS/AJAX.
- Live-search на `/karteien/` не должен раскрывать данные без корректной серверной проверки прав.
