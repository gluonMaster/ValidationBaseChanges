# Инструкция для Суперадмина (мультигод 2024–2026)

Эта инструкция объясняет, как пользоваться централизованным Excel‑файлом суперадмина, который умеет работать с базами 2024/2025/2026 из одного файла.

## 1) Что нужно заранее

- Excel на компьютере суперадмина, макросы разрешены (Enable Content).
- Доступ к облачным папкам, где лежат базы `KindElternDaten_24/25/26_front.accdb` (обычно OneDrive/SharePoint, синхронизировано локально).
- В Windows должна быть доступна компонента для работы с Access из Excel (DAO/ACE). Если раньше суперадминский файл уже подключался к Access, обычно всё уже установлено.
- Для выгрузок оплат: папка `C:\FamZahlung` (если её нет - создайте).

## 1.1) Dashboard: какие кнопки что делают (ваша сборка)

- `2024` / `2025` / `2026`  выбор года (`SelectYear24/25/26`)
- `Wartend`  загрузить pending + построить лист решений (`Dashboard_LoadPending`)
- `Ganz Datenbank`  загрузить всю базу года в `KarteiYY` (режим просмотра, `Dashboard_ImportFromBase`)
- `Zahlungen`  выгрузка оплат (`Dashboard_FamZahlungen`)
- `Datums Geschichte`  история за период (`Dashboard_DateRangeHistory`)
- `Database-Pfad`  настройка путей к базам (`Dashboard_ConfigureDatabase`)

## 2) Как "подключить" новую систему в файл суперадмина

Есть два варианта.

### Вариант A (рекомендуется): получить готовый файл

1. Получите обновлённый файл суперадмина (`KindElternDaten_Suprime.xlsm`) у ответственного за сборку/обновления.
2. Откройте файл и нажмите **Разрешить макросы** (Enable Content).
3. Перейдите на лист `Dashboard` (он может открыться автоматически).

На этом “подключение” завершено — дальше нужна только настройка путей к базам (см. раздел 3).

### Вариант B (для тех, кто обновляет вручную в VBA)

Если вы обновляете существующий файл суперадмина вручную (обычно это делает разработчик):

1. Откройте Excel → `Alt+F11` (редактор VBA).
2. Импортируйте модули из папки `Superadmin/` репозитория.
3. Обновите класс `DieseArbeitsmappe.cls` (это обработчики событий “Открытие/Закрытие”).
4. Проверьте, что макросы видны в `Developer → Macros`.

Если этот вариант вам непонятен — используйте Вариант A.

## 3) Первичная настройка баз (делается один раз на каждом компьютере)

Причина: файл суперадмина лежит локально у каждого суперадмина, а путь к облаку у всех разный.

1. Откройте лист `Dashboard`.
2. Нажмите кнопку **Database-Pfad** (или запустите макрос `Dashboard_ConfigureDatabase`).
3. В диалоге выберите “корневую” папку облака, где внутри есть каталоги:
   - `2024\Alarm\KindElternDaten_24_front.accdb`
   - `2025\Alarm\KindElternDaten_25_front.accdb`
   - `2026\Alarm\KindElternDaten_26_front.accdb`
4. Для проверки запустите `Dashboard_ShowConfig`:
   - должно показать ожидаемые пути и статус по каждому году (`ok`, `missing-file`, `not-configured`).

Если для какого‑то года база лежит в другом месте, используйте:

- `SelectDbFolder24`, `SelectDbFolder25`, `SelectDbFolder26` (выбор папки конкретного года).

Настройки сохраняются в скрытом листе `DBConfig` — руками его не редактируйте.

## 4) Основной пайплайн работы (на любой год 24/25/26)

Ниже описан стандартный цикл “посмотреть изменения → принять/отклонить → записать в базу”.

### Шаг 1. Выберите год

На `Dashboard` выберите год кнопкой (в вашей сборке это кнопки **2024 / 2025 / 2026**) или через список макросов:

- `SelectYear24` / `SelectYear25` / `SelectYear26`

Выбранный год хранится в `Dashboard!B2`. Все действия `Dashboard_*` используют этот год.

### (Рекомендуется) Настройте период для истории/комментариев на Dashboard

На `Dashboard` задайте период в блоке **Geschichte-Zeitraum**:

- начало: `E4` (день), `F4` (месяц), `G4` (год)
- конец: `H4` (день), `I4` (месяц), `J4` (год)

При выборе года кнопкой `2024/2025/2026` ячейки `G4` и `J4` автоматически заполняются соответствующим годом.

Этот период используется:

- при построении `grossGeschichteYY` (окно агрегации комментариев),
- при истории по записи `GeschichteYY` (фильтр по датам),
- при истории за период `GeschichteYY_Alle`.

### Шаг 2. Загрузите "pending" изменения из базы в Excel

Нажмите кнопку **Wartend** (или запустите макрос):

- `Dashboard_LoadPending`

Результат:

- данные из `pre_tblKartei` выбранного года загружаются на лист `KarteiYY` (например, `Kartei25`);
- автоматически строится лист решений `grossGeschichteYY` (например, `grossGeschichte25`).

### (Опционально) Загрузите всю актуальную базу года (режим просмотра)

Если нужно просмотреть текущее состояние базы выбранного года и/или построить историю по записи для **любой** строки (не только pending), нажмите кнопку **Ganz Datenbank** (или запустите макрос):

- `Dashboard_ImportFromBase`

Результат:

- данные из `tblKartei` выбранного года загружаются на лист `KarteiYY`;
- лист решений `grossGeschichteYY` **не** строится (это режим просмотра базы, без валидации).

### Шаг 3. Примите решения на листе grossGeschichteYY

1. Перейдите на лист `grossGeschichteYY`.
2. Для каждой записи выберите решение:
   - Колонка **AC**: `Approved` или `Declined`
   - Колонка **AD**: комментарий (только если `Declined`, по желанию)

Подсказка: можно использовать массовые действия (если они выведены кнопками/макросами):

- `ApproveAllPending24/25/26` — отметить всё как Approved
- `DeclineAllPending24/25/26` — отметить всё как Declined (может попросить общий комментарий)
- `ClearAllDecisions24/25/26` — очистить решения

### Шаг 4. Запишите решения обратно в базу (Sync)

Запустите:

- `Dashboard_SyncDecisions`

Результат для выбранного года:

- `Approved`: запись переносится из `pre_tblKartei` в `tblKartei`
- `Declined`: запись переносится в `decl_tblKartei` (с комментарием), и удаляется из `pre_tblKartei`

Важно: пока не сделан Sync, в базе ничего не меняется.

## 5) История изменений (History)

### История по одной записи

1. Перейдите на `KarteiYY`.
2. Выберите любую ячейку в строке нужной семьи/записи.
3. Запустите:
   - `Dashboard_SingleRecordHistory`

Результат: отчёт появится на листе `GeschichteYY`.

Примечание: если на `Dashboard` задан период (см. раздел 4), он автоматически применяется как фильтр по датам для истории по записи. Редактировать `GeschichteYY!B1/C1` вручную не нужно.

### История за период (массово)

1. На `Dashboard` укажите период в блоке **Geschichte-Zeitraum** (см. раздел 4).
2. Нажмите кнопку **Datums Geschichte** (или запустите макрос):
   - `Dashboard_DateRangeHistory`

Возможны два режима источника данных (если предлагается выбор):

- из `KarteiYY` (быстрее, но это “pending‑подмножество”),
- напрямую из базы года (`tblKartei`) — полный режим по базе.

Результат: отчёт появится на `GeschichteYY_Alle`.

## 6) Выгрузки оплат (FamZahlungen) по выбранному году

1. Убедитесь, что на `KarteiYY` загружены нужные данные (см. раздел 4, шаг 2).
2. Нажмите кнопку **Zahlungen** (или запустите макрос `Dashboard_FamZahlungen`).

Результат: в `C:\FamZahlung` появятся файлы с суффиксом года, например:

- `EltKosten_25.xlsx`, `EltKostenNH_25.xlsx`, `EltKostenInd_25.xlsx`

Замечание: отчёты строятся по данным листа `KarteiYY`. Если `KarteiYY` содержит только `pre_tblKartei` (pending), отчёт будет неполным. Для полного отчёта сначала загрузите **всю базу года** кнопкой **Ganz Datenbank** (`Dashboard_ImportFromBase`).

## 7) Новые записи (Neu) — только для 2026

Для 2024/2025 новых записей уже не ожидается.

1. Запустите:
   - `Dashboard_RefreshNeu`
2. Список появится/обновится на листе `Neu`.

## 8) Что происходит при открытии и закрытии файла

### При открытии

- Показ/создание `Dashboard`.
- Возможна автоматическая попытка обновить `Neu` (2026), но без навязчивых диалогов, если база ещё не настроена.

### При закрытии

- Очищаются “рабочие” листы `Kartei24/25/26` и `grossGeschichte24/25/26` (строки 3+).
- Не очищаются: `Dashboard`, `DBConfig`, `NeuConfig`, `Neu`, `GeschichteYY`, `GeschichteYY_Alle`.

Практическое правило: если вы не сделали `Dashboard_SyncDecisions`, то просто закроете файл — решения не попадут в базу, а рабочие листы очистятся.

## 9) Частые проблемы и решения

### “База не найдена” / `missing-file`

1. Запустите `Dashboard_ConfigureDatabase` и укажите корневую папку облака.
2. Проверьте, что облако синхронизировано локально (файл `.accdb` реально есть на диске).
3. Если структура папок отличается — используйте `SelectDbFolder24/25/26`.

### Нет “pending” записей

- В выбранном году `pre_tblKartei` пустая — значит на валидацию ничего не пришло.

### Выгрузка оплат пустая/неполная

- Проверьте, какие данные загружены в `KarteiYY`. Если это только “pending”, отчёт будет неполным.

### Ошибка DAO/Access при запуске макросов

- Обычно означает, что на компьютере нет нужной компоненты Access Database Engine.
  Обратитесь к ответственному за IT/установку Office.
