# Инструкция по миграции в новый календарный год (2026)

## Обзор

Данная инструкция описывает процесс подготовки файла Admin к новому календарному году. Миграция включает:

- Удаление устаревших записей (KN-маркеры, сиротские Zahlung)
- Перенос данных второго полугодия в первое
- Пересчёт месячных начислений по актуальным ценам
- Сохранение нового файла и создание базы данных Access

## Предварительные требования

1. **Резервная копия:** Перед началом миграции создайте резервную копию текущего файла `KindElternDaten_25_Admin.xlsm`
2. **Закрытые сессии:** Убедитесь, что никто другой не работает с файлом
3. **Синхронизация:** Все pending-изменения должны быть обработаны Суперадмином до миграции

## Запуск миграции

### Шаг 1: Открытие файла

Откройте текущий файл Admin (`KindElternDaten_25_Admin.xlsm`).

### Шаг 2: Запуск процедуры миграции

1. Нажмите `Alt+F11` для открытия редактора VBA
2. Нажмите `Ctrl+G` для открытия окна Immediate
3. Введите команду и нажмите Enter:

```vba
ImNeuenJahr_26
```

Или запустите макрос через меню:

- Вкладка "Разработчик" → "Макросы"
- Выберите `ImNeuenJahr_26`
- Нажмите "Выполнить"

### Шаг 3: Подтверждение

Система запросит подтверждение:

> **Neues Jahr Vorbereitung**
>
> Moechten Sie die Daten fuer das Jahr 2026 vorbereiten?
> Diese Aktion kann nicht rueckgaengig gemacht werden.

Нажмите **Ja** для продолжения или **Nein** для отмены.

### Шаг 4: Выбор папки для сохранения

После обработки данных откроется диалог выбора папки:

1. Выберите папку для сохранения нового файла
2. Нажмите "Auswaehlen"

Файл будет сохранён как `KindElternDaten_26_Admin.xlsm`.

**Важно:** Выбранная папка автоматически записывается в ячейку `Kartei!X1` — это базовый путь для подключения к базе данных Access.

### Шаг 5: Создание базы данных

После сохранения файла автоматически создаётся база данных Access в подпапке `Alarm`:

```
[выбранная папка]\Alarm\KindElternDaten_26_front.accdb
```

Если подпапка `Alarm` не существует, она будет создана автоматически.

После создания базы данных файл Excel сохраняется повторно, чтобы зафиксировать обновлённое значение `X1`.

### Шаг 6: Завершение

При успешном завершении отобразится сообщение:

> Vorbereitung fuer das Jahr 2026 wurde erfolgreich abgeschlossen.

## Что происходит при миграции

### 1. Удаление строк с маркером KN

Все строки, где колонка T содержит "KN" (без учёта регистра), удаляются. Это записи, помеченные как "Kein Nachweis" — без подтверждения.

### 2. Удаление сиротских Zahlung-строк

Если для FamilyID существуют только строки с `D = "Zahlung"` и нет содержательных строк (с именем ребёнка), такие Zahlung-строки удаляются.

### 3. Перенос полей второго полугодия

Для каждой содержательной строки (где `D ≠ "Zahlung"`):

| Источник | Назначение                | Описание     |
| -------- | ------------------------- | ------------ |
| O → J    | Группа 26/2 → Группа 26/1 | Предмет      |
| P → K    |                           |              |
| Q → L    |                           |              |
| R → M    | Цена 26/2 → Цена 26/1     | Базовая цена |
| S → N    |                           | Примечания   |

После переноса колонки O–S очищаются.

### 4. Расчёт месячных начислений (U–AF)

#### Специальный случай: Nachhilfe/NH/Ind./VSpE

Если в O (до переноса) содержится:

- "NH" (с учётом регистра)
- "Nachhilfe" (без учёта регистра)
- "Ind." (без учёта регистра)
- "VSpE" (без учёта регистра)

→ Все месяцы U–AF устанавливаются в **0**.

#### Стандартный расчёт

Логика зависит от наличия маркера "O/V" в колонке S:

**Ветка A (есть O/V):**

- U (январь) = значение из AF (декабрь прошлого года)
- V–Z (февраль–июнь):
  - Если R = AE → используется R
  - Если R ≠ AE → используется AE, и M обновляется на AE
- AA (июль) = 0

**Ветка B (нет O/V):**

- U–AA (январь–июль):
  - Если R = AF → используется R
  - Если R ≠ AF → используется AF, и M обновляется на AF

После расчёта колонки AB–AF обнуляются.

### 5. Перенос служебных колонок

| Источник | Назначение |
| -------- | ---------- |
| AP → AK  | Extra1     |
| AQ → AL  |            |
| AR → AM  |            |
| AS → AN  |            |
| AT → AO  |            |

После переноса колонки AP–AT очищаются.

### 6. Обновление заголовков

| Ячейка | Значение    |
| ------ | ----------- |
| A1     | 1           |
| J2     | Gruppe 26/1 |
| O2     | Gruppe 26/2 |
| M2     | Preis 26/1  |
| R2     | Preis 26/2  |

### 7. Сортировка

Данные сортируются по:

1. Колонка B (Parent) — по возрастанию
2. Колонка A (FamilyID) — по возрастанию
3. Колонка D (Child) — по возрастанию

## Неизменяемые данные

Следующие колонки **никогда не изменяются** при миграции:

| Колонка | Описание                  |
| ------- | ------------------------- |
| AV (48) | ID записи                 |
| BA (53) | Статус (PENDING/DECLINED) |
| AZ (52) | История изменений         |

## Отладка и проверка


## Обработка ошибок

### Нет данных для обработки

Если на листе Kartei менее 3 строк, появится сообщение:

> Keine Daten zum Verarbeiten gefunden (weniger als 3 Zeilen).

### Отмена сохранения

Если пользователь отменяет выбор папки:

> Speichern abgebrochen. Die Vorbereitung wurde nicht abgeschlossen.

В этом случае данные уже трансформированы, но файл не сохранён. Рекомендуется:

- Либо сохранить файл вручную
- Либо закрыть без сохранения и начать заново

### Ошибка сохранения

При ошибке записи файла:

> Fehler beim Speichern der Datei: [описание ошибки]

## Модули VBA

Миграция реализована в следующих модулях:

| Модуль                | Назначение                                         |
| --------------------- | -------------------------------------------------- |
| `nj_NewYearEntry`     | Оркестратор сценария, точка входа `ImNeuenJahr_26` |
| `nj_NewYearTransform` | Бизнес-логика трансформации данных                 |
| `nj_NewYearAccess`    | Создание базы данных Access                        |

## Поддержка

При возникновении проблем:

1. Проверьте наличие резервной копии
2. Запустите `nj_DebugCheckNewYearState` для диагностики
3. Проверьте окно Immediate (Ctrl+G) на наличие ошибок
